Predictive Modeling

Predictive Modeling

Role in the Career Evaluation Product

Machine learning methods can extend the descriptive job-market analysis by identifying patterns among postings and helping organize opportunities into meaningful groups.

At the current stage of the project, the primary focus is exploratory analysis and skill-gap assessment. The cleaned dataset and variables developed in Modules 2 and 3 establish the foundation for more advanced modeling in later project phases.

Potential Modeling Approaches

Future analysis may include:

  • clustering job postings based on skills, experience, salary, and other characteristics;
  • grouping employers or roles with similar hiring profiles;
  • identifying segments of opportunities that may be more attainable for early-career candidates;
  • developing a structured career-fit or opportunity score; and
  • comparing job-market segments based on compensation and skill requirements.

Candidate Features

Potential variables for modeling include:

  • salary midpoint;
  • minimum years of experience;
  • education requirements;
  • remote-work classification;
  • employer;
  • geographic location; and
  • technical skill indicators.

These features can help distinguish different types of opportunities within the Data Scientist occupational market in Software Publishers.

Next Stage

The final modeling approach will be selected based on the project question and the quality of the available variables. Any model or segmentation method will be evaluated and interpreted in the context of career decision-making rather than used as a purely technical exercise.

From Plan to Model

The sections above outlined the modeling options. We carried out two of them. The structured opportunity score is on the Career Evaluation page. The salary model below uses the candidate features listed above (experience, education, remote status, employer, and skills), plus the role segments added in Module 5.

Salary Model

What We Modeled and Why

This section predicts the salary of a posting from things a job seeker can see or control: the type of role, how much experience it asks for, whether it’s remote or full-time, education, and which skills it lists.

We used the same three models from our individual Module 5 assignment: linear regression, polynomial regression, and a random forest. That assignment used PySpark on about 19,000 postings. This dataset has 681 postings with salary data, so we used pandas and scikit-learn instead.

Feature Engineering

Only postings with salary information are used (684 of 1,016). Three postings with midpoints below $30,000 or above $400,000 were dropped as likely data errors, leaving 681.

model_df = panel[panel["SALARY_MIDPOINT"].between(30000, 400000)].copy()

# Experience is missing for some postings. Fill with the median and keep a flag
# so the model can tell "not stated" apart from a real value.
model_df["exp_missing"] = model_df["MIN_YEARS_EXPERIENCE"].isna().astype(int)
model_df["min_experience"] = model_df["MIN_YEARS_EXPERIENCE"].fillna(
    model_df["MIN_YEARS_EXPERIENCE"].median()
)

# Polynomial term: experience squared
model_df["min_experience_sq"] = model_df["min_experience"] ** 2

# One 0/1 column per role segment. Data / BI Analyst is left out so it becomes
# the comparison group: every segment coefficient is "compared with analysts."
segments = pd.get_dummies(model_df["role_segment"], prefix="segment", dtype=int)

The inputs are:

  • Role segment (compared with Data / BI Analyst)

Linear Regression

def coef_table(model):
    ci = model.conf_int()
    table = pd.DataFrame({
        "Estimate": model.params,
        "Std Error": model.bse,
        "P-Value": model.pvalues,
        "CI Lower": ci[0],
        "CI Upper": ci[1],
    })
    return table.round({"Estimate": 0, "Std Error": 0, "P-Value": 3, "CI Lower": 0, "CI Upper": 0})


def test_metrics(name, predictions):
    return {
        "Model": name,
        "RMSE ($)": mean_squared_error(y_test, predictions) ** 0.5,
        "MAE ($)": mean_absolute_error(y_test, predictions),
        "R²": r2_score(y_test, predictions),
    }

The linear model explains about 30% of the variation in salary on the test set, and its predictions are off by about $34,000 on average.

Each estimate is the change in salary for that factor, holding everything else constant. The ones that are clearly different from zero (p < 0.05):

  • Experience: each extra year required adds about $3,600.
  • Architect / Engineer roles pay about $43,800 more than analyst roles. Consultant / Implementation roles pay about $15,400 less, and AI Data Trainer roles about $61,000 less.
  • Remote postings pay about $16,200 less. That’s the opposite of what we found in the individual assignment, where on-site roles paid less. In this industry, many of the remote postings are sales and analyst-relations roles, which pay less.
  • Excel in the skills list goes with about $39,000 lower pay, which likely reflects that Excel-heavy postings are more junior or business-side roles.
  • Each additional listed skill adds about $430.

Oracle as the employer, education level, and most individual technical skills are not significant once role and experience are accounted for.

Polynomial Regression

In the individual assignment, adding experience squared improved the model: salary rose faster at higher experience levels. We tested the same idea here.

poly_model = sm.OLS(y_train, sm.add_constant(X_poly_train)).fit()
poly_preds = poly_model.predict(sm.add_constant(X_poly_test, has_constant="add"))

print(test_metrics("Polynomial", poly_preds))
print("Experience squared p-value:", round(poly_model.pvalues["min_experience_sq"], 3))
{'Model': 'Polynomial', 'RMSE ($)': 48229.69306516823, 'MAE ($)': 34083.52321276138, 'R²': 0.29948693609376487}
Experience squared p-value: 0.862

Unlike in the individual assignment, the squared term did not improve the model here. Its p-value is about 0.86, the test R² stayed the same, and both AIC and BIC were slightly worse, which suggests salary in this market rises at a fairly steady rate with experience.

Random Forest

The random forest uses the same inputs as the linear model. It can pick up interactions that a linear model misses, like experience mattering more in some segments than others. We used 300 trees, with each leaf needing at least 5 postings, which limits overfitting on a small dataset.

forest_model = RandomForestRegressor(
    n_estimators=300, min_samples_leaf=5, random_state=42
).fit(X_train, y_train)

forest_preds = forest_model.predict(X_test)

The random forest is the best model, with an R² of about 0.57 and an average miss of about $25,000, compared with about 0.30 and $34,000 for the linear model. Between the two linear models, the plain linear model is preferred on both AIC and BIC.

All three models still pull predictions toward the middle. They underpredict the highest salaries and overpredict the lowest, the same pattern as in the individual assignment.

In the individual assignment, the random forest reached an R² of about 0.15 using only experience, employment type, and remote status, and we noted that adding job type and skills would likely help more than changing algorithms. With role segments and skills included here, the random forest reached about 0.57, which supports that idea.

To check the random forest result wasn’t a lucky split, it was also run with 5-fold cross-validation:

Example Profiles

The random forest can estimate pay for example postings. Each one assumes a full-time role, a bachelor’s degree, and a typical number of listed skills (22).

def estimate(**settings):
    row = pd.DataFrame([{column: 0 for column in X.columns}])
    row["is_full_time"] = 1
    row["skill_count"] = 22
    for column, value in settings.items():
        row[column] = value
    return forest_model.predict(row)[0]


profiles = pd.DataFrame([

Limitations

  • About a third of postings have no salary and can’t be used.
  • The best model explains about half of the variation in salary. The rest comes from things the data doesn’t capture, like company size, exact location, or the details of the job.
  • Linear model coefficients show associations, not causes. The negative remote and Excel estimates most likely reflect which kinds of jobs list those things.
  • Role segments come from title keywords and can be wrong for some postings.
  • The example profiles are rough estimates for illustration.
